# 交割与验收契约 v0

**用途：**第13组成员可分别使用不同AI。正式交割以仓库文件为准；本契约用最少字段保证A组内部、B组内部和A/B之间都能接上。报告目录及章节归属见[第13组报告蓝图](第13组报告蓝图与初步分工.md)。

## 1. 共同格式与位置

正式产物统一放在仓库根目录 `work/`。G0按 `project_docs/README.md` 核对18券、共同投资问题和A/B交付，即可开工；正式G1输入仍须登记**已通过的精确文件路径与版本**。建议按版本保存 `work/universe_v1.csv`、`work/A_diagnostics_v1.csv`、`work/B_diagnostics_v1.csv`、`work/joint_candidates_v1.csv`；B四模块分别放在 `work/B_methods/B1/` 至 `B4/`，个券卡、案例和成稿分别放 `work/A_cards/`、`work/cases/`、`work/deliverables/`。提问和状态变更分别记在 `work/issues_v1.csv`、`work/decisions_v1.csv`。B1候选底表当前为 `work/B_methods/B1/base_v1.csv`，B2–B4输出和未签认状态见[B工作台](../work/B_methods/README.md)；修订生成 v2 等新文件，不覆盖已验收版本，下游引用原版本失效时标为待复核。

交割表头统一记录：`目标验收关口`、`产物类型`、`版本`、`研究组号`、`行情观察时点`、`公开资料可得截止`、`负责人`、`复核人`、`来源/输入版本`、`状态`。`版本`填v1、v2等，`状态`只填草稿、待复核、已通过。例如G0后交、供G1验收的B1底表，目标验收关口写`G1`，产物类型写`B1底表`。CSV第一行为字段名，元数据列逐行填写；Markdown在开头填写。行情原则上取约定交易日收盘，公开资料须在截止前可得；后见信息另起版本或标为事件更新，不能默默补进旧价结论。证据引用精确到文件/页码，或数据字段、统计区间和计算位置。修订要写一句变更原因。

A/B全池诊断的`方向`只填**正向、负向、中性、证据不足**。A对发行人、正股、信用与条款形成资产质量/风险判断，B对同一观察价下的量化估值与风险收益形成判断；两者参照G0共同投资问题，但均非最终推荐票。中性表示证据充分但暂无明确方向；证据不足表示关键资料缺失，不能判断，不得把两者合并或把两线结论平均。

债券与正股代码均按**保留前导零的六位文本**处理；`债券唯一键=交易所:六位债券代码`，正股使用独立的`正股唯一键`，交易所映射由G0核实。禁止用简称连接表。G1按债券唯一键对账：第13组应恰好**18个唯一键**，A/B各键各一行且与G0清单完全相同；重复、缺失、多出或时点不一致即退回。

### A组两层卡片：逐券证据与六人可讲的比较过程

A负责人组织全池逐券完成同一结构，具体由谁调研、撰写和复核由她安排。**第一层是18张逐券卡**：核心判断控制在约一页，证据来源可附后。每个条目区分事实与判断；不适用或查不到的数据写明原因，不用空泛公司简介替代分析。

逐券卡统一采用下列**三块表格**，不要把八项要求连写成一段报告。每个证据格先列事实、期间、公开日期和来源页码；相邻解释格只写它如何影响A判断。格内可以写“未查得＋原因”，不能空白或让AI补造。

| 卡头字段 | 必填内容 |
| --- | --- |
| 身份与责任 | 债券唯一键、正股唯一键、A覆盖单元、个券主责、复核人、版本及状态 |
| 问题与A初判 | 本券最值得判断的问题；A方向四值、置信度及一句理由（不是最终推荐票） |
| 时间口径 | 财务观察期、资料可得截止、行情观察时点、共同投资问题版本；不同日期不得混写 |

| 证据板维度 | 已核验事实及来源 | A侧解释／与同单元券的差异 |
| --- | --- | --- |
| 行业与发行人 | 业务/竞争位置、需求或成本驱动 | 为什么影响经营；哪些券并不可比 |
| 经营与现金流 | 同期可比的收入、利润、经营现金流及变化 | 主要经营正证或负证 |
| 信用缓冲 | 债务、现金可用性、偿付压力、评级等适用事实 | 说明限制，不能把不同期限余额直接相减 |
| 转债条款 | 核查强赎、回售、下修、到期等适用条款；只列会改变投资问题的事实 | 条款事实与价值推断分开；债底、估值和期权价值交B |

| 判断与补证字段 | 必填内容 |
| --- | --- |
| 主证与最强反证 | 各列一条最能支持、最能挑战A方向的证据；硬风险单列 |
| 正股机制 | 上行驱动、下行机制及1—2个可验证条件；不以无依据目标价代替判断 |
| A初筛与改判条件 | 对同单元券的相对优劣、未知项、补查责任；什么新事实会改变方向 |
| 留给合流的问题 | 如有影响投资取舍的价格/风险假设，写问题及所需时点或输入；没有就写“暂无”，不强编，也不代填B结论；这不是B逐券必答工单 |
| 报告/PPT摘录 | 报告第3部分可复用的一句话；PPT最值得讲的一条证据或图表需求 |

三张**真实、待复核**的填写示例见[A6覆盖单元试填](../work/A_cards/A6_2026H1_真实试填.md)；其中已经发生的条款事件被单列，不冒充经营正证。

**第二层是六份A覆盖单元小结**，由每位上台发言的A成员本人完成。默认把自己的三张逐券卡压缩成一页比较表和一条可讲的推理链：`比较问题 → 三券共同口径 → 决定性差异与反证 → A初筛倾向 → 等待B核验的问题`。小结至少点到负责的每只券，但可把讲述重点放在最有分歧的一只；不要求平均分配发言秒数，更不能预先把每个覆盖单元硬指定一个最终推荐券。G1合流前，小结只陈述A的过程和倾向，不假装知道B结论或最终池状态。

覆盖单元小结统一使用以下**可填结构**；A负责人可调整排版和内部比较指标，但须保留字段，以便汇入报告第3.1部分和PPT。若实际分工不是每人三券，表格行数随主责券数调整，仍须六人各有一份署名小结。

```text
覆盖单元ID／成员／负责债券唯一键／研究卡版本／资料截止：
本单元共同投资问题（一句话）：
共同比较口径（同期间、同定义的2–3项关键观察；不可比之处说明）：
逐券比较（每券一行）：债券｜支持A判断的关键事实及来源｜最强反证/未知项｜A四值倾向及置信度｜相对其他券的差异
初筛推理链：先比较什么 → 哪项证据改变了判断 → 为什么三券倾向相同或分化？
可能的合流问题：逐券或共用的价格/风险假设；没有就写“暂无”，不代填B结论。
用于报告3.1的一句话与图表/来源索引：
用于PPT的一页提纲：问题 → 决定性对照 → 最大反证 → 初筛倾向 → B待检验问题；约70秒。
```

A负责人开工后可用两张试填卡校准共同财务观察期、最低可比指标、条款来源、方向/置信度示例，以及覆盖单元小结的长度和复核标准；行业补充指标由她安排。这是A组内部质量检查，不是G0放行条件。她检查18张卡能汇成A诊断表、六份小结能进入报告第3部分并支撑六位成员各约70秒的PPT发言。全池初筛允许“证据不足”，但须写明缺口和补查责任。G1后再对活跃候选追加深入证据，不让全池卡承担六案长报告的篇幅。

### B组统一的方法包

B四席位的初步方法、数据表和任务已见[独立工作文件夹](../work/B_methods/README.md)，具体人名与细分工作量由B负责人落实。B方法包首先服务B自己的问题：**同一观察价下，价格结构、可能收益、下行和交易约束是否相称，何种情景会使判断反转**；详见[可执行方案的B路线](可执行方案-v0.md)。每个方法包提交：`研究问题 → 计算/模型假设 → 输入字段/期间 → 适用券输出与解释 → 未覆盖券及原因 → 缺失与异常 → 稳健性/失效条件 → 对投资结论的解释`。量化模型须可复算且能解释结论，不能只把指标排成图；若本组18只券的横截面和字段覆盖不足，改用情景/敏感性模型，不声称小样本统计显著。现有四套全池计算表尚未经过成员署名复核，不能冒充G1输入。B负责人把验收后的方法包合成每券一行的B全池**状态**诊断：明确填`量化覆盖状态`，有数据就报告结果，无足够数据且没有可信替代判断时，`方向`填`证据不足`，说明缺口和补数或替代路径；内部信号冲突保留，不能由AI擅自平均。B在G1前独立完成这些交付；A问题仅在合流时作为选题线索，不以逐题回复作为B全池交付的验收条件。

| G1 | 总负责人已组织候选观点头脑风暴并记录参与者、备选主张和反方问题；全池每券恰有一个五值去向；两侧有独立竞争候选；分歧、暂不深研及证据缺口有理由和责任人；活跃券有A/B对口人与合稿人，问题台账可追踪 | 补证或回查全池；一侧不足3个可信候选记有条件通过与补证期限，不强凑 |
| G2 | 恰好3推荐+3不推荐；每案A/B证据、最大反证、冲突解释和失效条件齐全；六案代表性已核对；未入选理由、反对意见和所用版本可复述 | 退回补证；候补须先完成状态变更及复核，再记录改动 |

进入活跃池的最低证据是：方向、一个可复核机制、主要反方证据或未知项、来源和观察时点；分歧池另须有G2前能回答的明确问题。正式六案必须有两条路线的实质证据。不推荐须有风险收益不成立的独立论证，不能仅因未进推荐池或排位靠后。六案代表性核对发行人、细分行业与投资命题；双行业组说明覆盖考虑而不设硬配额。课后提交以课程原始要求为准；“行业”采用分组表第二张工作表的原文，课件邮箱在提交前核实。

## 4. 不同AI会话怎样接棒

任何新会话先读原始作业要求、`project_docs/README.md`、本方案和当前关口的已验收产物，再接任务。提示词至少写：`目标验收关口 / 产物类型 / 研究组号 / 负责债券唯一键或B方法 / 共同投资问题版本 / 两个时点 / 输入文件路径与版本 / 输出路径 / 负责人`。每券一张卡且每卡只有一位写入者；每个方法包也有唯一写入者。A/B全池表各由路线负责人唯一合并，总负责人唯一维护联合表。AI只能在负责范围内产出，事实与推断分开，缺数据写缺口；不能用聊天摘要代替交割文件，也不能替另一条路线编造结论。

交割消息写：`文件路径、版本、状态、关键结论、未解决问题、下一位负责人`。接受方按上表验收，不合格时在文件修订记录写明退回问题。G1/G2只引用 `project_docs/README.md` 指定的已通过版本；任何上游更正需新文件与变更原因，受影响下游退回待复核。外部数据仓库只登记路径、字段与版本，不复制整库；共享衍生底表遵守使用权限。
