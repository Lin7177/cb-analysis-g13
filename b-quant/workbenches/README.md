**执行顺序：**B1锁底表及条款候选 → B2、B3平行研究同一18券 → B4基于三者做情景和交叉复核 → B负责人查看[18券证据总览](evidence_board_v0.csv)并逐券签认 `work/B_diagnostics_v1.csv`。G1只接收签认版本。当前四个文件夹里已有脚本、CSV和一张图，属**负责人搭建的计算起点**，不等于四位成员已完成署名研究，也不代表B方向已确定。总览中的自动标记只提示复核议题，不是买卖评分。

B1 已有[真实公告核验样板](B1/公告核验样板.md)，示范来源、日期、条款事件及剩余核验。它只覆盖三券的部分公告证据；18 券的 T 日有效条款仍待逐券签认。

四张 `逐券…表_v0.csv` 由 `create_review_sheets.py` 一次生成，已逐键预填可复算数字，留出各自应写的来源、解释、反证和复核状态；生成器拒绝覆盖现有文件。成员填完时另存 `v1`，由复核人验收，**不要把 v0 的空栏当作“已研究”**。

开工时请四位成员共同读[负责人预研观察 v0](负责人预研观察-v0.md)：里面已有基于18券真实数据的四模块问题、数字与相互冲突。成员的职责是复核、补证和挑战这些初判，交出自己的署名结论；这份底稿本身不进入G1。

在仓库根目录依次运行：

B2与B3可并行；B4须等前三项。所有结果精确连接 `work/universe_v1.csv` 的18个 `债券唯一键`。输入行情见[公开日频数据与边界](../../data/curated/README.md)；条款候选来自公开数据接口，18券报价均与T日行情一致，但**公告生效日仍未核验**。若修订公式、样本窗口或T日，另存新版本并让下游重算，不覆盖已验收版本。每位成员在本文件夹补 `研究结论-v1.md`：`研究问题 → 数据与口径 → 全池发现 → 代表券正反两面 → 失效条件/缺口 → 对B全池判断的影响 → 来源和图表`，署名并请另一人复核。每人最后提炼一页图和约60–90秒讲稿；整组20分钟需留给A六人和共同六案，最终秒数由展示协调人排练后定。

**交接门槛：**B1确认输入版本和缺口；B2、B3各自覆盖18券且至少解释三只不同机制的券；B4解释冲突并标注哪些情景只是机械敏感性。B负责人不能用四张图平均成总分，须对18券各写独立方向（正向/负向/中性/证据不足）、最强反证、覆盖状态及方法引用；未核实的条款不能支撑正式G1判断。
